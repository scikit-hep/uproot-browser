# AGENTS.md

This file provides guidance to agents when working with code in this repository.

## Overview

uproot-browser is a terminal tool to browse and inspect ROOT files (the file format used in high-energy physics). It exposes three subcommands — `tree`, `plot`, and `browse` (default) — built on the Scikit-HEP stack: uproot (file reading), awkward (arrays), hist (histogramming), plotext (text plots), Click (CLI), and Textual (TUI).

## Commands

```bash
uv sync                              # set up the dev environment
uv run pytest                        # run the test suite
uv run pytest tests/test_tui.py      # run one test file
uv run pytest -k test_browse_plot    # run a single test by name
prek -a --quiet                      # lint everything (ruff, mypy, etc. — preferred over pre-commit run -a)
uv run uproot-browser browse --testdata uproot-Event.root   # run the app against a testdata file
```

Nox sessions (`nox -s lint | tests | pylint | minimums | build`) run the same things in isolated environments; `minimums` tests against lowest-direct dependency versions. mypy runs in `strict` mode over `src`. Ruff uses `select = ["ALL"]` with a curated ignore list — expect strict linting.

## Architecture

A backend-neutral node model sits between the file formats and everything that displays them:

- **`src/uproot_browser/nodes.py`** — the abstract node classes. `Node` (a backend object plus its `parent`/`key`, hence `path`, `name`, `meta()` for the tree label, `children`, and `resolve(path)` for `/`- or `:`-separated selections, which uses the longest run that is a child key and gives a `FailedNode` for a key that fails to load); `Folder` (`keys()`, `lookup(key)`); `Root` (a node that opened a file: `open_source(var)` for Dump & Quit, `lookup_source`, `close()`); `DataTree` (a columnar dataset with `num_entries`); `Plottable` (`to_histogram(bins)`, `dump_hist(width)`, `plottable`, `ndim`); `Histogram` (any object with `axes`/`to_hist()`); `Column` (an array leaf: `numeric`, `entry_count`, `typename`, `read()`, `read_source(var)`, with default histogramming and dump text); `Pair` (two `Column`s as a 2D plot; a `FailedNode` re-raises its error). `data_tree()` finds the dataset a node belongs to (the `tree` name in expressions) and `data_tree_source` its dump line. This is the whole interface a backend implements.
- **`src/uproot_browser/backends/`** — the backends and their registry. A backend is a module with `matches(spec)` and `open_spec(spec, *, parent, key) -> Node`, importable without its optional dependencies (`open_spec` raises `ModuleNotFoundError`, and the registry adds the install hint from `Backend.extra`). `backends()` loads every backend from the `uproot_browser.backends` entry-point group (the built-in `directory` and `uproot` backends are registered there too, in `pyproject.toml`). There are two roles: a format backend claims a spec from its text alone (a suffix, no remote I/O; `uproot` does not claim a directory), and formats are asked first, in name order; the `directory` backend (`CONTAINER`) is asked last; `uproot` (`FALLBACK`) opens what nothing claims. `open_path(spec)` opens a `path` or `path:key` spec with the first that matches, `claims(spec)` asks the formats only, `split_spec` splits the spec, and `select_key` gives the node at the key (a key that does not load raises). `uproot.py` holds every uproot-specific detail (`UprootFile`, `UprootDirectory`, `UprootTTree`, `UprootRNTuple`, `UprootBranch`, `UprootField`, `UprootHistogram`, and the `wrap` dispatch). `directory.py` is the directory-of-files browser, on any fsspec filesystem (local, or a remote URL such as `osdf://`): `Directory` lists what some format claims, and each file is a `LazyRoot` that opens with its own backend on first use and forwards to the opened root. A remote URL is a directory if it ends with `/` or the filesystem says so (HTTP is never probed); remote subdirectories are listed without a search for files. Supporting a new format means a new module like `uproot.py`, plus an entry point in the `uproot_browser.backends` group.
- **`src/uproot_browser/tree.py`** — builds a `rich.tree.Tree` from a node (`make_tree`, `print_tree`).
- **`src/uproot_browser/plot.py`** — backend-neutral plotting: `plot` draws a node into a plotext figure (`plottable_node` re-raises a `FailedNode` error or rejects a node that is not `Plottable`), the mpl path reuses the same calls. The optional `expr` string is `eval`'d with the histogram bound to `h` and the raw dataset to `tree` (used by the TUI's plot-input box for slicing, e.g. `h[:]`). `dump_expr`/`dump_plotext`/`dump_mpl` give the matching standalone source.
- **`src/uproot_browser/plot_mpl.py`** — alternate matplotlib rendering path for `plot --image`, `plot --save`, and `browse --image` (requires the `[image]` extra). `src/uproot_browser/tui/image_plot.py` (`MPLPlot`) is the TUI side of this path.
- **`src/uproot_browser/plotext_compat.py`** — version adaptor: all plotext drawing goes through the `PlotextFigure` protocol, which mirrors the native plotext 6 figure API. On 6+, `make_figure` returns the native figure directly; on 5.2.8+ it returns an adaptor over the module-level API (no 2D heatmaps — raises a clear error). The `minimums` nox session exercises the 5.x path.

The CLI (`src/uproot_browser/__main__.py`) is the Click entry point (`uproot-browser` script). It uses `click-default-group` so a bare invocation defaults to `browse`. Heavy imports (matplotlib, the TUI) are deferred inside command bodies to keep startup fast. `--testdata` resolves a filename through `skhep_testdata.data_path`.

### TUI (`src/uproot_browser/tui/`)

Textual app, entry point `browser.py:Browser`. Layout is composed in `Browser.compose`: the built-in `Header` (the file path is the `sub_title`), a tabbed left panel (Tree / Info, where Info lists the installed dependencies), a main `ViewWidget`, and a `RightPanel` (`right_panel.py`) with axis ranges, image scale, and the theme selector. `RightPanel` posts `RightPanel.LimitsChanged` and `RightPanel.ScaleChanged` to the app. The command palette has a Help command (`Browser.get_system_commands`). Styling lives in `browser.css`.

Communication is **message-driven** (`messages.py` defines `UprootSelected`, `RequestRender`, `RenderFailed`). Flow when a user picks a tree node:

1. `left_panel.py:UprootTree` (a `textual.widgets.Tree[Node]`) posts `UprootSelected` with the displayed root node and the selected path below it. Each expand reads the children in a threaded worker (`_load_in_thread`), so the UI thread does no file reads. A remote URL root is a `LazyRoot`, so the app shows before the file opens. A node whose `is_loaded` is false (an unopened file, a remote directory not listed yet) is not entered by the jump list.
2. `Browser.on_uproot_selected` creates a plot item and assigns it to `view_widget.item`. A plot item is a frozen dataclass that subclasses `PlotItem` (`tui/plot.py`): `Plotext` for text plots, `MPLPlot` for image mode. It compares by value (the caches have `compare=False` and copies share them), and a change is a copy made with `dataclasses.replace` (`with_theme`, `with_expr`, `with_axis_limits`).
3. `ViewWidget` (a `ContentSwitcher` in `viewer.py`) switches between the logo, an error traceback, or the plot window based on `item`'s type.
4. `PlotItem.display` switches to the window of the item, and `ViewWidget.request_render` posts `RequestRender` (for `Plotext`, after the refresh); a resize of the view or of the plot pane (`PlotResized`, posted by the `ResizeNotifier` text and image plot widgets, for example when the entry box shows) does the same through `ViewWidget.on_resize` (debounced). `Browser.on_request_render` gets a copy of the item at the size of the view (`with_view_size`), puts it in `view_widget.item` without the watcher, and, if it is not equal to the last rendered item, starts `render_item`. This is a **threaded exclusive Textual worker** that calls `item.render()` off the UI thread and gives the result to `item.show` via `call_from_thread`. This threading matters — plot generation must not block the event loop. Each started render gets a new render ID. A render that raises posts `RenderFailed` with its ID; `Browser.on_render_failed` drops a report with an old ID or about an item that is not current, and then clears the view and warns (`EmptyTreeError`), keeps the item editable and notifies (`ExpressionError`), or shows the traceback (other errors). The worker reads the data outside the locks (`_PLOTEXT_LOCK` for the global plotext figure, `plot_mpl.RENDER_LOCK` for matplotlib); only the draw holds a lock. The entry box (`PlotInput`) and the Plot button are handled by `ViewWidget` with `@on`.
5. Every wait in a worker thread runs in `StatusBar.running(label)` (`tui/status.py`), which shows a box with the label and a progress bar above the footer after a short delay; the old plot stays until the new one is ready. The bar has no percentage until the work calls `uproot_browser.progress.report(fraction)` (`progress.py`, a context variable, so a backend reports without any TUI import). The uproot columns read one basket or cluster range at a time to report, only when a listener is set. The render worker also installs `progress.cancel_when`, so a report in a superseded render raises `progress.CancelledError` and the read stops early. A remote file given on the command line is a `LazyRoot`, so it opens in a load worker too.

Plotext theme dictionaries are registered through `add_theme` (`plotext_compat.py`), called at import time in `browser.py`, to match light/dark terminal backgrounds. `d` ("Dump & Quit") exits printing equivalent Python code to reproduce the current plot: `tui/plot.py:dump_header` opens the file(s) through the selected node's `Root` and binds `item` (or `x_item`/`y_item`), then the plot item appends the node's `dump_hist`, the expression, and the drawing code. Press `/` to open a fuzzy finder over tree nodes (`tui/jump.py`); `UprootTree.request_jump_candidates` builds the list in a worker and caches it for each file.

Tests use Textual's `run_test()` pilot harness (`pytest-asyncio` in auto mode). Note the double `await pilot.pause()` after actions that trigger the threaded plot worker — the second wait lets a posted `RenderFailed` settle. The render replaces `view_widget.item` to give it a size, so read the item again after a render.

## Conventions

- New object or format support goes into a backend: subclass the node classes in `nodes.py` (mypy reports missing abstract members) and give the nodes from the backend's `open_spec` (for uproot, register the type in `wrap`), instead of adding `isinstance` chains to the core.
- The package is fully typed (`py.typed`, mypy strict). `_version.py` is generated by hatch-vcs from git tags — never edit it.
- Two files carry per-file ruff ignores in `pyproject.toml`: `__main__.py` and `tui/image_plot.py`, both `PLC0415` (deferred imports). Respect these rather than fighting them.
